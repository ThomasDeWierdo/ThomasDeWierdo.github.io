The Brain System

 This system I feels shows my capability of creating and understanding very complex systems and how I can automate complex functions to create a very simple and reusable interface to use elsewhere.
 This is the most interesting of the systems I've made for Perastra, and it is essentially a neural network that aims to mimic the brain of real animals as closely as possible, using hormones like dopamine, adrenaline, cortisol, and organizing the data in a way very similar to real brains, all while still keeping it performant enough for anybody to run it on their own computer. This originally started as a way to automate the process of creating separate AI for every creature and giving some organicness to each creature's behavior, but it turned into something that I've never seen in another game, and drastically changes how you play the game. Enemies can adapt to what you're doing, or run if they know they can't beat you. In most games, you have to predict what the enemy will do next; in this game, you have to know what the enemy can't do, and act in a way to avoid any unpredictable actions. It's almost like all the creatures are controlled by other people, all playing a different game with different goals. Fighting a boss that uses this system would be extremely unique compared to combat in other games. Neural networks have been made before, but I've never seen one in a video game before where you actually have to play with or against creatures using it.
 Earlier I mentioned that the mechanical system becomes very interesting in conjunction with this, and that's because I'm planning on allowing the player to create their own neural computer blocks to create their own robots, letting you give it control to something like a weapon on a vehicle, or allow it to control its own creation to do something independently. All the brain system does is take in and return float values ranging from 0 to 1, which is perfect since the cables and signals in the mechanical system are just float values ranging from 0 to 1. This will make it pretty simple to implement this into a placeable block once I get to that point. Sorry that I don't have many actual tests and examples and that a few things are still theoretical, but the hardest part is already done.
 Now I should say that this system isn't done, however it does work. The main thing is that I've only recently found out how brains reason, and I am yet to implement the required changes. I already know how to do so and have planned the architecture, but I've been focusing on other systems so I haven't yet. 1: I need to implement parallel processing, allowing the brain to think about multiple things at the same time and merge separate concept for new ideas. I can use the GPU for this so it won't harm performance much. 2: I need to change the structure to allow concepts to connect to other concepts - that's essentially what gives the brain reasoning. 3: I need to add 'emotional imprint' to concepts, allowing the brain to understand what concepts are bad or good and to come up with new ideas through past experience without having to be actively experiencing something. That allows the brain to think ahead and make plans.
 Above is a video of the brain system at work (sped up 10x). All I've done to implement this brain into the test creature is to give it sensory input, motor output, and drives. You can see that it starts out making the wrong movements, but over time it slowly learns what outputs to perform to get what it wants.
 Sensory inputs are just simple functions that return float values ranging from 0 to 1 (I call them Float01 values). In this case, I had 3 sensory inputs for vision, and 2 inputs for the direction of the target position. You can have as many sensory inputs as you want, however it will take longer for it to learn the more inputs there are. I will definitely be testing something like full color vision once I make the changes I described earlier to the system.
 Then the motor outputs are just simple functions that take in Float01 values. The brain system, through its Float01 values as input, will reason and find corresponding Float01 values for outputs. These output values are just plugged directly into the motor outputs functions you provide it. In this case, I just had walk and jump outputs. I was able to manipulate one Float01 value to allow it to move either left or right with only a single output value. You can also have as many motor outputs as you want, it just will take longer to learn with more values to think of.
 Then, the final components are the drives. Drives give rewards when they are raised and punishments when they are lowered. These can also be made with simple functions that just return a simple 'fulfillment' float value. Then the drives modify the levels of dopamine and other neuromodulators automatically depending on how the fulfillment value changes. In this test, I had two drives: one that raises when it goes closer to the target point, and one that acts as an energy that lowers when the creature jumps. The second drive prevents the creature from constantly jumping, as it learns that to maximize happiness, it should find the route to the target point with the fewest amount of jumps possible.
 There is also functionality to make multiple brain sectors each in charge of different tasks, allowing you to speed up the learning process by splitting up inputs and outputs across different sectors, though my test creature was simple enough that I only used one. It also allows you to reuse sectors across different brains, meaning you can just apply the same walking sector immediately to skip most of the learning process for that creature.
 This general architecture also means it wouldn't be very difficult to implement this in any game I want. I would love to try to mod another game in the future and implement this system in its enemies.

World Generation System

 This system I think shows how my capability to create simple, yet versatile systems to speed up the design process without making more obscure mechanics harder to implement.
 The world generation system is one of my newer systems, and my main goal for this was to make it as quick and simple as possible to create new biomes, and make the code required to design a biome as readable as I possible. Since it's new, I've only created one biome using it, but it has worked pretty well.

This is the code that designs the generation for the Onimellow Forest. 

public class OnimellowForest_WorldGen : WorldGen
{
    static PerlinNoiseVertical1D WallCutoff = new(min: 0, max: 5, scale: 5);
    static PerlinNoiseHorizontal1D SurfaceCutoff = new(min: 5, max: 20, scale: 40);
    static PerlinNoise2D CaveCutout = new(min: 0, max: 1, xScale: 20, yScale: 10);
    static PerlinNoiseHorizontal1D ClimbooPlacement = new(min: -20, max: 5, scale: 10);

    static StructurePlacer1D SurfaceForegroundStructures = new(placeEveryXChunks: 10, retryCount: 30,
        structures: new StructureOption[] {
            new(Structures.OnimellowTree, placeChance: 0.7f, leftPadding: 1, rightPadding: 1),
            new(Structures.ClichMound, placeChance: 0.5f, leftPadding: 1, rightPadding: 1),
            new(Structures.Climboo, placeChance: 0.5f, leftPadding: 1, rightPadding: 1) 
        });

    static StructurePlacer1D BackgroundClichMound = new(placeEveryXChunks: 10,
        structures: new StructureOption[] {
            new(Structures.ClichMound, placeChance: .2f, leftPadding: 3, rightPadding: 3)
        });

    const int onimellowTreeYOffset = -3;
    const int clichMoundYOffset = -4;
    const int climbooYOffset = -3;
    const int backgroundClichMoundYOffset = -7;

    public override WorldGenOutput Run(in WorldGenContext ctx, WorldGenOutput output)
    {
        float wallCutoff = WallCutoff[ctx];
        if (wallCutoff >= GetDistanceFromBiomeLeft(ctx) || wallCutoff >= GetDistanceFromBiomeRight(ctx))
            return output.OutOfBounds();

        float surfaceCutoff = SurfaceCutoff[ctx];
        if (ctx.y > surfaceCutoff)
        {
            output.SetIds(ItemId.Air);

            if (BackgroundClichMound.FindOverlappingStructure(ctx, out var mound))
            {
                mound.y = Mathf.FloorToInt(Mathf.Min(SurfaceCutoff[mound.x], SurfaceCutoff[mound.x + mound.structure.Variants[mound.variant].Width])) + backgroundClichMoundYOffset;
                output.Set(mound[ctx].Invert());
            }

            if (SurfaceForegroundStructures.FindOverlappingStructure(ctx, out mound))
            {
                int yOffset =
                    mound.structure == Structures.OnimellowTree ? onimellowTreeYOffset :
                    mound.structure == Structures.ClichMound ? clichMoundYOffset :
                    climbooYOffset;
                mound.y = Mathf.FloorToInt(Mathf.Min(SurfaceCutoff[mound.x], SurfaceCutoff[mound.x + mound.structure.Variants[mound.variant].Width])) + yOffset;
                output.Set(mound[ctx]);
            }

            return output;
        }

        if (ctx.y > surfaceCutoff - 5)
            return output.SetIds(ItemId.Clich);

        output.frontBlock = ItemId.Murk;
        if (CaveCutout[ctx] > 0.7f)
            output.frontBlock = ItemId.Air;
        output.backBlock = ItemId.Murk;

        return output;
    }
}
