The Brain System

 This system I feel shows my capability of creating and understanding complex systems and how I can automate complex functions to create simple and reusable interfaces.

Overview

 The brain system is a general-use neural network heavily inspired by brains in real animals, using hormones like dopamine, adrenaline, and cortisol, organizing the data in a way very similar to real brains, all while still keeping it performant enough for anybody to run it on their own computer. This originally started as a way to automate the process of creating separate AI for every creature and to give some organicness to each creature's behavior, but it turned into something that I've never seen in another game, and drastically changes how you play the game. Enemies can adapt to what you're doing, run if they know they can't beat you, or find new solutions to whatever situation it encounters. In most games, you have to predict what the enemy will do next; in this game, you have to know the limitations of the creature, and act in a way to avoid any unpredictable actions. Fighting a boss that uses this system would be extremely unique compared to combat in other games. Neural networks have been made before, but I've never seen one in a video game where you actually have to play with or against creatures using it.
 Earlier I mentioned that the mechanical system becomes very interesting in conjunction with this, and that's because I'm planning on allowing the player to create their own neural computer blocks to create their own robots, letting them give it control to something like a weapon on a vehicle, or allow it to control its own creation to do something independently. All the brain system does is take in and return float values ranging from 0 to 1, which is perfect since the signal values in the mechanical system are just float values ranging from 0 to 1. This will make it pretty simple to implement this into a placeable block once I get to that point.

Technical Deep-dive

 Data is stored in the brain using objects called assemblies. This relates to the cell assembly theory, where neurons pair together into larger groups called cell assemblies. Grouping them together also means I don't have to simulate every individual neuron, while still retaining a very similar behavior. There are three assembly types: sensory, motor, and internal. Sensory assemblies are activated based on the current sensory input going into the brain, and each sensory assembly has different sensitivity to each sensory input. Motor assemblies are activated by internal assemblies and trigger motor outputs. Internal assemblies just represent any concept, and what that concept is is decided by how the assemblies are connected to each other. Every assembly can connect to other assemblies through synapses, which are one-way paths that propagate signals through assemblies. Through certain functions of the brain, assemblies and synapses can be created or destroyed, and the rate that this occurs is dependent on neuromodulators.
 Neuromodulators, more commonly known as hormones, are used to modify how frequently certain functions in the brain occur. For this brain system, I only use dopamine, adrenaline, serotonin, cortisol, and acetylcholine. Each of these are in charge of quite a bit, but in simple terms, dopamine reinforces synapses, serotonin suppresses modifications suppresses signal propagation, adrenaline suppresses modifications and increases signal propagation, cortisol increases random trial-and-error learning, and acetylcholine increases brain modification strength.
 To manually create a custom brain, you have to make three things: sensory input, motor output, and drives. Sensory inputs are simple functions that return float values ranging from 0 to 1 (I call them float01 values). In this case, I had 3 sensory inputs for vision, and 2 inputs for the direction of the target position. You can have as many sensory inputs as you want, however it will take longer for it to learn the more inputs there are. I will definitely be testing something complicated like full pixel vision sometime in the future, just to see how well it can handle that much data.
 Motor outputs are simple functions that take in Float01 values. The brain system, through its float01 values as input, will reason and find corresponding float01 values for outputs. These output values are plugged directly into the motor output functions you provide it. In my example, I just had walk and jump outputs. I was able to manipulate one float01 value to allow it to move either left or right with only a single output value. You can also have as many motor outputs as you want, though it will take longer to learn with more values to think of.
 Then, the final components are the drives. Drives give rewards when they are raised and punishments when they are lowered. These can also be made with simple functions that just return a simple 'fulfillment' number. Then the drives modify the levels of the neuromodulators automatically depending on how the fulfillment value changes. In this test, I had two drives: one that raises when it goes closer to the target point, and one that acts as an energy that lowers when the creature jumps. The second drive prevents the creature from constantly jumping. Since it learns that to maximize happiness, it should find the route to the target point with the fewest amount of jumps possible. You can make these drives very simple, perhaps just hunger, thirst, and pain drives are all you need for a survival-based creature, then the creature can run through simulations to figure out how to fulfill those needs.
 This general and simple interface will make it extremely easy to create new creatures for my game, as I don't have to manually create any AI or behaviors per-creatuer, I just make the biological structure of the creature and it figures out how to behave to survive on its own. This also means it may be pretty simple to mod this into other games. It would be cool to have it control a player in Minecraft, or give it control of an enemy in REPO.

Performance and Optimization

 A system like this I'm guessing has never been in a game for two reasons: 1, most people have no idea where to even start with implementing this, and it just sounds ridiculous to say "I'm going to add a neural network to my game to control all the enemies", and 2, making this actually perform well on most computers sounds like an impossible task. A big performance gain is to use the GPU to propagate signals through assemblies as this allows every assembly to run at once. The GPU is able to handle almost all the logic, the hard part was just figuring out how to structure it in a way to allow that.
 So, in a ticking frame for the brain, it first runs each drive function, using simple math to modify each neuromodulator level. It then also calls the sensory inputs to get the current sensory data. Then, those neuromodulators can modify some further simplified modifier values. Then the GPU is called to run on every assembly at once. Since brains have maximum sizes, I can have the GPU still run on available slots for assemblies that aren't there yet, meaning if it calculates that it should possibly create a new assembly with the given modifier values, it can set that assembly to active immediately. The GPU will be able to a lot of work, and by the end of it, the system will have access to all the motor output values, which can then be plugged directly into the motor functions given. This really is not that much work for computers to handle. There is also another thing I can use to optimize, and I can do that by storing every single assembly across every single brain in a single, large array. This means instead of calling the GPU kernel once per brain, it calls it once per tick, meaning performance drops very little with more brains active in the world at once. I also have to split up the three types of assemblies into separate arrays, but it still gives a pretty constant speed with more brain power. If your computer can handle one brain, most of the time it should be able to handle as many as you want. Some of these optimizations aren't made yet, but I understand them extremely well and they will be implemented with the other changes I have planned (described in the Future Development section).

Future Development

 Now I should mention that this system isn't done, however it is in a state that works. The demonstration shown earlier is how the system currently looks now, but there are some major changes that will make it work so much better in more complex situations. The reason for this is that I've only recently found out how brains reason, and I am yet to implement the required changes. A while ago I spent 3 weeks unable to work on my game so figuring this out was my only way of feeling productive. I already know how to implement this and have planned the architecture (the technical deep-dive was describing how the system works with these changes), but I've been focusing on other systems so I haven't implemented it quite yet.
 1: I need to implement parallel processing, allowing the brain to think about multiple things at the same time and merge separate concept for new ideas.
 2: I need to edit the structure to allow assemblies to connect to other assemblies by adding internal assemblies - that's essentially what gives the brain reasoning.
 3: I need to add 'emotional imprint' to concepts, allowing the brain to understand what concepts are bad or good and to come up with new ideas through past experience without having to be actively experiencing something. That allows the brain to think ahead and make plans.
 4: Some changes to how serotonin affects the brain due to a better understanding of what purpose it actually serves. You might think that dopamine would be the reward and adrenaline the punishment, but it's much more nuanced than that, and serotonin seems to be more of what a punishment in a simpler punishment-reward system is useful for.
